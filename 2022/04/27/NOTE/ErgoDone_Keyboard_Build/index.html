ErgoDone: Building a Custom Ergonomic Keyboard

Created2022-04-27
|Post View:

Before We Begin

The idea of building an ergonomic keyboard with my own two hands actually came from overhearing my little princess complain that her shoulders hurt after long stretches at the computer. Add to that the arrival of spring, with flowers blooming and everything coming back to life, and the fact that her birthday was coming up, and my first-ever custom keyboard burst onto the scene. To be honest, I agonized over the birthday gift options for quite a while. After vetoing a Raspberry Pi Zero kit and a modded NumWorks calculator one by one, the pragmatist in me finally settled on a target (although she caught me red-handed not long after the project got going), and I set off in grand style down the road of a made-to-measure, heavily modded keyboard.

Gathering Materials

The PCBs

The prototype I picked for the keyboard is the open-source project ErgoDone. Compared with the original ErgoDox, its main differences are:

  • The controller is switched from a Teensy 2.0 to a Pro Micro, so I can program it easily with the Arduino IDE
  • The IO expander chip is switched from an MCP23018 to an MCP23017, which seems to just save a bit of cost
  • So that some users can use it as a one-handed keyboard, the main half is moved from the right hand to the left, and the left half can be used on its own
  • The LEDs are moved from under the switches to a vertical row in the top-right corner of the left half, which is more intuitive

There’s an officially licensed ErgoDone shop on Taobao (China’s big online marketplace), but the kit had already been discontinued. So I followed the trail into the K.T.E.C. QQ group chat, and with the help of some kind group members I found the source files the shop owner had put on GitHub. I zipped up the gerber folder and placed an order straight away with JLCPCB (a PCB fab)~ (Later my little princess pointed out that JLCPCB charges an extra 50 RMB process fee to change the solder mask from green to blue. Waaah, my poor little savings–)

Buying Parts

The user requirements for this keyboard were designed as follows:

  • Works both as a Bluetooth keyboard and as a wired keyboard
  • Can run on its own lithium battery or be powered from the computer
  • Customizable keyboard layout and macro keys
  • Above all, comfortable to type on

So I bought the following parts:

  1. 1N4148 diodes *76
  2. Cherry brown switches *76
  3. Keycaps *76: four 2U, twelve 1.5U, sixty 1U
  4. PCB-mount 2U stabilizers *4
  5. Arduino Pro Micro, micro USB version *1
  6. MCP23017 *1
  7. 2.2KΩ resistors *2
  8. 220Ω resistors *3
  9. Blue-white LEDs *3
  10. 0.1uF ceramic capacitor *1
  11. Type-C lithium battery charging/protection module *1
  12. Three-position slide switch *1
  13. 5000mAh lithium battery *1
  14. USB mini B connector 54819-0519 *1
  15. Micro USB extension connector *1
  16. 3.5mm TRRS jacks SJ-43514 *2
  17. Aputure TRRS-to-TRRS cable *1
  18. HX-03 Bluetooth module *1
  19. M2 female-female copper standoffs, 19mm *14
  20. M2 screws, 8mm *28

Circuit Design

ErgoDone’s keyboard circuit was already designed. I opened the gerbers in KiCad, exported them as a PCB, and ended up with a schematic. You can see it works as a key matrix:

Soldering the Components

With all the materials in hand, the first step was to solder the Pro Micro onto the left-hand board, then the resistors, diodes, USB mini B connector, micro USB extension connector, 3.5mm TRRS jack and the LEDs. On the right-hand board I soldered the MCP23017, resistors, diodes and LEDs, then tested whether the two halves could be connected with the TRRS cable.

Soldering the Switches

First solder the four stabilizers onto the PCB. Then pick the four corner positions on the PCB, insert brown switches through the plate, solder them, and test continuity. Once the switches are all soldered, you can put on the keycaps.

Battery Assembly

Connect the battery’s positive and negative leads to the lithium battery charging/protection module. The positive output goes to the three-position slide switch and then to VCC on the PCB, and the negative goes to GND. This powers the Bluetooth keyboard.

Bluetooth Module

Connect VCC and GND to the positive and negative pads on the PCB. For RX and TX, you can use the IO pins of the two remaining LEDs to hook it up to the keyboard.

Programming

To make it easy to use and develop further, I wrote the main code as an Arduino library called Ergodone. I also made a few small changes to the existing HID-Projects on GitHub, adding a Bluetooth keyboard configuration and example to fit this keyboard’s needs.

Next comes the design of the Ergodone library. The left half is controlled directly by the Pro Micro, so I wrote ArduinoProMicroMatrix.h to read and write the digital pins for scanning.

Here, begin initializes the keyboard, scan does real-time scanning, getRows returns the number of rows, getCols returns the number of columns, and isOn checks whether the key at a given row and column is pressed, i.e. whether a finger is sitting on its head (is on?). setLEDs sets the LED state and is still in development.

During one scan, select_row selects a row by pulling it low, read_cols reads which columns currently have keys pressed, and unselect_row deselects that row.

Correspondingly, the right half is controlled by the MCP23017 IO expander chip connected over serial, so I wrote Mcp23017Matrix.h to drive it.

All of the above only reads the positions of pressed keys. To send key codes to the computer, besides KeyboardMap.h for the key mapping, you can use HID-Projects to emulate keyboard input; you just need to call the Keyboard class.

Modifying HID-Projects

The main change is adding a BluetoothKeyboard series to MultiReport. It also inherits from the DefaultKeyboardAPI parent class. This new subclass sets up a software serial port at initialization and, in actual use, sends the key codes.

Testing Bluetooth

Testing the Left Half

In the examples, left_hand_test checks continuity on the left half. If any key can’t be read, resolder it. The test program prints, in hex, the key states of whichever row changed, which usually means one press and one release.

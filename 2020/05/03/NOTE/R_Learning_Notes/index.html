IX Importing Data

In research settings, we need to import data into R from a file, a database, or some other source. Currently, one of the most common ways of storing and sharing data for analysis is through electronic spreadsheets. A spreadsheet stores data in rows and columns; it is basically a file version of a data frame. When saving such a table to a computer file, we need a way to define when a new row or column ends and another one begins. This in turn defines the cells in which single values are stored.

When creating spreadsheets with text files, like the ones created with a simple text editor, a new row is defined with return and columns are separated with some predefined special character. The most common characters are the comma (,), semicolon (;), space ( ), and tab (a preset number of spaces or \t). Here is an example of what a comma-separated file looks like when opened with a basic text editor:

The first row contains column names rather than data. We call this a header, and when we read in data from a spreadsheet, it is important to know whether the file has a header or not. Most reading functions assume there is a header. To find out whether a file has a header, it helps to look at the file before trying to read it. This can be done with a text editor or with RStudio. In RStudio, we can do this by opening the file in the editor, or by navigating to the file location, double-clicking on the file, and clicking View File.

However, not all spreadsheet files are in a text format. Google Sheets, which are rendered in a browser, are one example. Another example is the proprietary format used by Microsoft Excel. These can’t be viewed with a text editor. Despite this, the format is still widely used because Microsoft Excel software is so widespread.

1. Paths and the Working Directory

The first step when importing data from a spreadsheet is to locate the file containing the data. We need to let the R function doing the importing know where to look for the file containing the data. 1.1. The File System

Think of your computer’s file system as a series of nested folders, each containing other folders and files. Data scientists refer to folders as directories. The folder that contains all other folders is called the root directory. The directory in which we are currently located is called the working directory. The working directory therefore changes as you move through folders: think of it as your current location.

1.2. Relative and Full Paths

The path of a file is a list of directory names that can be thought of as instructions on which folders to click on, and in what order, to find the file. If these instructions are for finding the file from the root directory, we refer to it as the full path. If the instructions are for finding the file starting in the working directory, we refer to it as a relative path.

1.3. The Working Directory

It is recommended to write only relative paths in your code. The reason is that full paths are unique to your computer, and you want your code to be portable. You can get the full path of your working directory without writing it out explicitly by using the getwd function.

If you need to change your working directory, you can use the function setwd, or you can change it through RStudio by clicking on “Session”.

5. Text Files versus Binary Files

Extracting data from a spreadsheet stored as a text file is probably the easiest way to bring data from a file into an R session. But spreadsheets are not always available, and the fact that you can look at a text file does not necessarily mean that extracting data from it will be simple.

6. Unicode versus ASCII

A pitfall in data science is assuming a file is an ASCII text file when, in fact, it is something else that looks a lot like an ASCII text file: a Unicode text file.

Everything on a computer ultimately needs to be converted to 0s and 1s. ASCII is an encoding that maps characters to numbers. ASCII uses 7 bits (0s and 1s), which results in $2^7 = 128$ unique items, enough to encode all the characters on an English-language keyboard. However, other languages use characters not included in this encoding. For example, the é in México is not encoded by ASCII. For this reason, a new encoding using more than 7 bits was defined: Unicode. When using Unicode, you can choose between 8, 16, and 32 bits, abbreviated UTF-8, UTF-16, and UTF-32 respectively. RStudio actually defaults to UTF-8 encoding.

A discussion on StackOverflow: R on Windows: character encoding hell.

7. Organizing Data with Spreadsheets

Things to keep in mind:

  • Be consistent - Before you start entering data, make a plan. Once you have a plan, be consistent and stick to it.
  • Choose good names for things - You want the names you pick for objects, files, and directories to be memorable, easy to spell, and descriptive. This is actually a hard balance to achieve, and it does take time and thought. One important rule to follow is do not use spaces; use underscores _ or dashes - instead. Also, avoid symbols; stick to letters and numbers.
  • Write dates as YYYY-MM-DD - To avoid confusion, use this global ISO 8601 standard.
  • No empty cells - Fill in all cells and use some common code for missing data.
  • Put just one thing in a cell - It is better to add columns to store the extra information rather than having more than one piece of information in one cell.
  • Make it a rectangle - The spreadsheet should be a rectangle.
  • Create a data dictionary - If you need to explain things, such as what the columns are or what the labels used for categorical variables are, do this in a separate file.
  • No calculations in the raw data files - Excel lets you perform calculations. Do not make this part of your spreadsheet. Code for calculations should be in a script.
  • Do not use font color or highlighting as data - Most import functions are not able to import this information. Encode this information as a variable instead.
  • Make backups - Back up your data regularly.
  • Use data validation to avoid errors - Leverage the tools in your spreadsheet software so that the process is as error-free as possible and does not cause repetitive stress injuries.
  • Save the data as text files - Save files for sharing in comma- or tab-delimited format.
